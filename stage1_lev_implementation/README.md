# Решения заданий 1–3

Самостоятельные реализации по методичкам:

- [Светофор](../openspec/stages/stage-1-simpy/exercise-01.md)
- [Параллельное движение](../openspec/stages/stage-1-simpy/exercise-02.md)
- [Случайные потоки](../openspec/stages/stage-1-simpy/exercise-03.md)

Время задаётся в секундах, расстояние в метрах, скорость в м/с.
Нужны Python 3.10+ и SimPy 4.1.2. Зависимостей от `stage1-dao` нет.

## Запуск

Все команды выполняются из корня `UrbanFlow`. При использовании существующего
окружения достаточно установить зависимость и запустить пакет:

```powershell
& ./.venv/Scripts/python.exe -m pip install -r stage1_lev_implementation/requirements.txt
& ./.venv/Scripts/python.exe -m stage1_lev_implementation
```

На другой машине окружение можно создать командой `py -3 -m venv .venv`.

Выбор задания, seed, полный журнал и выгрузка:

```powershell
& ./.venv/Scripts/python.exe -m stage1_lev_implementation --exercise 3 --seed 7 --log
& ./.venv/Scripts/python.exe -m stage1_lev_implementation --output stage1_lev_implementation/results
```

Каждое задание также запускается отдельно:

```powershell
& ./.venv/Scripts/python.exe -m stage1_lev_implementation.exercise01
& ./.venv/Scripts/python.exe -m stage1_lev_implementation.exercise02
& ./.venv/Scripts/python.exe -m stage1_lev_implementation.exercise03
```

## Как устроены решения

`exercise01.py` содержит требуемый генератор `traffic_light`. Он перебирает
циклическое расписание фаз и записывает цвет до `yield env.timeout(...)`.
Остановка через `env.run(until=180)` оставляет девять включений: события
на самой границе 180 с не обрабатываются. Без переданного журнала генератор
печатает переключения в консоль.

В `exercise02.py` оба процесса `move` регистрируются до запуска среды.
Каждый ждёт свой интервал `distance / speed`. Автомобиль заканчивает путь
в 10 с, пешеход подходит к краю дороги в 20 с; всё моделирование занимает 20 с.

В `exercise03.py` работают отдельные процессы `car_source` и `pedestrian_source`.
Общий `arrival_clock` выдаёт экспоненциальные ожидания, включая ожидание первого
участника. Интенсивности 360 и 180 в час переводятся в 0.1 и 0.05 в секунду.
Потоки используют отдельные `Random(seed)` и `Random(seed + 1)`, поэтому
изменение интенсивности одного не меняет времена другого.

Автомобилю назначается отдельный процесс движения из задания 2, а пешеходу
сразу записываются появление и прибытие с одинаковым временем. Движения
пешехода и перехода дороги в задании 3 нет. Это соответствует методичке;
в просмотренном эталоне из `03_random_flows` пешеход ошибочно проходит 28 м.

Источники допускают появления только при `t < 600` и заканчивают работу
в 600 с. Среда затем выполняет оставшиеся поездки. Здесь используется
`env.run()` без числового ограничения. Для ID служат отдельные счётчики
с префиксами `car-` и `pedestrian-`.

Для экспериментов функции `run` принимают именованные параметры длительностей,
расстояний, скоростей и интенсивностей. Нулевая интенсивность отключает поток;
отрицательные, бесконечные и NaN-параметры отклоняются. Все вызовы возвращают
новый `Result`, не печатают и не меняют глобальное состояние `random`.
Результат содержит `events`, `participants`, `finished_at` и метод `summary()`.

`data.py` описывает записи, `reporting.py` отвечает за вывод и экспорт,
`__main__.py` предоставляет общий CLI. Старые модели и черновики заданий 4–7
удалены из этой реализации.

## Выгрузка

Для каждого задания создаётся подкаталог `exercise01`, `exercise02` или `exercise03`:

| Файл | Содержимое |
| --- | --- |
| `events.csv` | `time`, `actor`, `kind`, `action`: переключения, старты, появления и прибытия |
| `participants.csv` | `id`, `kind`, `appeared_at`, `arrived_at` |
| `summary.json` | Номер задания, seed, время окончания, число событий и участников |

В первом задании CSV участников содержит только заголовок. CSV записываются
в UTF-8 с BOM; время в файлах не округляется. Консоль показывает шесть знаков
после запятой. Повторный экспорт перезаписывает файлы выбранного задания.

## Проверки

```powershell
& ./.venv/Scripts/python.exe -m unittest discover -s stage1_lev_implementation/tests -v
```

21 тест проверяет времена из методичек, параллельность, границу генерации,
завершение поздних поездок, независимость потоков, воспроизводимость,
нулевое время пешеходов в задании 3, сохранение числа участников и экспорт.
Есть проверка средних чисел участников на 200 фиксированных seed.
Тесты не используют эталонные модули.

Результаты контрольного запуска: [RESULTS.md](RESULTS.md).
